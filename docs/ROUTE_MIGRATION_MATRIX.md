# Route Migration Matrix

Audit date: 2026-11-02  
Canonical host in current code: `https://www.siryushub.com`  
Status vocabulary: KEEP, REWRITE, MOVE, MERGE, RETIRE, INVESTIGATE.

This matrix records the routes generated by the 2026-11-02 production build, dynamic paths that did not generate output, and historical aliases found in `public/_redirects` and `public/.htaccess`. Proposed target paths are architecture decisions for review, not confirmation that a subdomain or deployment is live.

## Migration rules

- Keep all current source and CMS content until its owner, canonical target, redirects, and backup are verified.
- Use local paths while subdomains are not live. Switch to `artists.siryushub.com`, `collective.siryushub.com`, or `growth.siryushub.com` only after preview and custom-domain verification.
- A redirecting route must not also ship an independently canonical full HTML document.
- Preserve article/event slugs, publication dates, authors, Sanity document IDs, and asset references.
- PAVO Create is always external at `https://pavocreate.com`; never create `/pavo`.
- Acoustic Rwanda must not appear in new navigation, search, cards, or sitemap. Its old route needs an approved 301 target or 410 response.

## Sitemap and indexing corrections

The 2026-11-02 generated XML sitemap contains both slash and non-slash versions for many routes because `astro.config.mjs` adds manual `customPages` on top of discovered routes. It also includes `/home/`, Hidaya's archive, legacy services/projects paths, and other URLs without a settled indexing policy.

Required changes after route approval:

1. Remove manual duplicate `customPages` or generate them from the single route registry.
2. Exclude all redirect responses, retired routes, pagination routes with no content, and intentional archives marked noindex.
3. Publish exactly one canonical URL format.
4. Use CMS publication/update dates instead of assigning the build timestamp to every route.
5. Decide whether legal pages belong in the sitemap rather than filtering them accidentally.
6. Test the final XML and every redirect on the actual Cloudflare Pages preview before DNS cutover.
